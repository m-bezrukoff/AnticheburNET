# Установка AnticheburNET на OpenWrt 25.12

AnticheburNET предназначен для всех устройств с OpenWrt **25.12**. Поддерживаемые протоколы: **VLESS, Hysteria 2, XHTTP и AmneziaWG 3.1**. Опционально доступно полное ядро **Xray 26.10.21**. Текущий готовый комплект компонентов поддерживает target **mediatek/filogic** и **mediatek/mt7622**, arch **aarch64_cortex-a53**. Для обеих платформ используются одинаковые ARM64-пакеты программ; отдельная пересборка для MT7622 не нужна. Пакеты приложений собраны с SDK 25.12.3; модули `kmod-tun` и nft устанавливаются из feeds вашей прошивки и должны соответствовать её ядру. IPK из общего builder предназначены для старых OpenWrt и для этой цели не используются.

Это набор приложений, не образ firmware. CI проверяет исходники, создание APK и работу точных ARM64-бинарников под QEMU. Работа fw4/TPROXY и скорость VPN на физических устройствах пока не испытаны. Xray 26.10.21 — отдельный опциональный пакет с исправлением доверия сертификатам.

Три Go-бинарника упакованы UPX 5.2.1; полные GeoIP/GeoSite сохраняются в gzip-архиве и проверяются/распаковываются только в RAM (`/var/run/anticheburnet-xray/assets`). Сборка считает файлы всех шести APK и их размещение в блоках 4 KiB; при размере больше 35 MB останавливается. Точные размеры находятся в `installed-sizes.txt`, сравнение способов сжатия — в `packing-comparison.csv` релиза. Рабочая RAM процессов и распакованных баз не уменьшается из-за сжатия; перед установкой проверяйте свободный overlay.

## Установка

Сохраните резервную копию настроек через LuCI / System / Backup, скачайте её на компьютер. Войдите по SSH под `root` и выполните одну команду:

```sh
( f="$(mktemp /tmp/anticheburnet-install.XXXXXX)" || exit 1; trap 'rm -f "$f"' EXIT; wget -T 30 -O "$f" https://raw.githubusercontent.com/m-bezrukoff/AnticheburNET/main/install.sh && sh "$f" )
```

Команда скачивает установщик с GitHub во временный файл и запускает его только после успешной загрузки. Сначала установщик предлагает `1) install` или `2) uninstall`; можно также ввести слово `install` или `uninstall`. Пустой или неверный ответ на вопрос о действии повторяет вопрос, а конец ввода останавливает скрипт без установки или удаления. После выбора `install` установщик спрашивает язык: **`1) English` — по умолчанию**, `2) Русский`. Enter или отсутствие ввода выбирает английский; неверный номер повторяет вопрос. Выбранный язык записывается в `luci.main.lang` после установки и применяется ко всему интерфейсу LuCI. Затем скачиваются **пять обязательных APK из одного последнего релиза**: AnticheburNET, LuCI, пакет русского перевода, sing-box extended и AmneziaWG. Пакет перевода входит в комплект при любом выборе языка. Пакеты устанавливаются одной транзакцией `apk add` после проверки каждого по `SHA256SUMS`; неполный релиз или неверная сумма останавливает установку до замены пакетов. Временные файлы удаляются после успешной установки; при ошибке после начала удаления проверенные APK сохраняются в указанном установщиком каталоге `/tmp` для восстановления до перезагрузки роутера. Опции `--install` и `--uninstall` пропускают выбор действия; установка по-прежнему спрашивает язык и при отсутствии ввода использует английский. Удаление не спрашивает язык.

Перед загрузкой пакетов проверяются OpenWrt 25.12, target `mediatek/filogic` или `mediatek/mt7622`, arch `aarch64_cortex-a53`, наличие `apk` и **64 MiB свободного `/tmp`**. После проверки новых APK установщик сохраняет настройки, останавливает сервисы и удаляет заменяемые пакеты, включая `sing-box`, `sing-box-tiny` и `sing-box-extended`. Оставшийся `/usr/bin/sing-box` принудительно удаляется, даже если не зарегистрирован в APK; при ошибке остановки или удаления установка прекращается. Настройки sing-box сохраняются. Проверка **свободного места в overlay** выполняется после удаления и `sync`, поэтому старый бинарник больше не блокирует замену из-за собственного размера. Используется значение `Available` из `df`, а не размер файлов `du`. Если заменяемых пакетов и бинарника нет, flash проверяется до остановки сервисов. Роутер должен иметь доступ к GitHub и репозиториям пакетов OpenWrt. Модули ядра и остальные зависимости скачиваются из feeds установленной прошивки, без сборки на роутере.

После проверки APK установщик составляет план удаления и проверяет обратные зависимости. Конфигурации и список пакетов сохраняются в `/root/anticheburnet-backups/<дата>-<pid>` с закрытыми правами доступа. Затем останавливаются заменяемые сервисы, восстанавливается DNS AnticheburNET и удаляются старые AnticheburNET/LuCI, их переводы, варианты sing-box, `anticheburnet-xray`, `anticheburnet-amneziawg` и конфликтующие `xray-core`, NextDNS, Passwall/Passwall2, https-dns-proxy с их интерфейсами. Зависимости, которые больше не нужны, удаляет APK; общие библиотеки и зависимости других приложений сохраняются. Установщик не применяет принудительное удаление обратных зависимостей. Если заменяемое ядро требуется приложению вне плана, установка останавливается до изменения сервисов. Конфигурации AnticheburNET/Xray/AWG возвращаются перед миграцией новых пакетов, поддерживаемая legacy-конфигурация переносится. Выполняйте установку по локальному SSH: используемый VPN прервётся на время замены. Архив конфигураций не является автоматическим откатом пакетов; при ошибке используйте сохранённые APK для повторной установки.

Успешная установка завершается сообщением `AnticheburNET <версия>: AnticheburNET, LuCI (en), sing-box extended, Xray and AmneziaWG installed` и указанием исходного релиза. Для русского языка в сообщении будет `LuCI (ru)`. Если установщик сообщил об ошибке, устраните указанную причину и повторите ту же SSH-команду.

После первой установки добавьте свои подключения и правила в LuCI и включите AnticheburNET. При обновлении восстанавливается прежнее состояние AnticheburNET. Xray и AWG по умолчанию выключены до добавления пользовательской конфигурации.

APK подписываются не ключом OpenWrt, поэтому установщик применяет `--allow-untrusted` только к локальным пакетам после проверки SHA-256. Обновить весь комплект можно повтором той же команды. Для старого общего сценария на других платформах используйте `sh install.sh --generic`: он устанавливает только AnticheburNET/LuCI и предлагает выбор sing-box, без Xray/AWG. Legacy compressed extended использует источник shtorm-7 и в полный комплект не входит.

## Удаление

На OpenWrt с `apk` доступна опция `--uninstall`. Для уже сохранённого скрипта:

```sh
sh install.sh --uninstall
```

Или загрузите установщик и передайте ему ту же опцию:

```sh
( f="$(mktemp /tmp/anticheburnet-install.XXXXXX)" || exit 1; trap 'rm -f "$f"' EXIT; wget -T 30 -O "$f" https://raw.githubusercontent.com/m-bezrukoff/AnticheburNET/main/install.sh && sh "$f" --uninstall )
```

Удаление не скачивает APK, не обновляет feeds и не выполняет установочные проверки свободного места на flash и в RAM. Нужны уже установленные `ucode`, `ucode-mod-fs` и `ucode-mod-uci`, чтобы корректно восстановить DNS. Перед остановкой сервисов сохраняются конфигурации и список пакетов в `/root/anticheburnet-backups/<дата>-<pid>`; место для этой резервной копии всё же необходимо. Не выполняйте удаление через VPN, который обслуживает AnticheburNET.

Удаляются AnticheburNET, его LuCI и переводы, Xray/AWG из комплекта и связанный с установленным AnticheburNET вариант sing-box. Автозапуск отключается, DNS возвращается в прежнее состояние, конфигурации и кэши AnticheburNET очищаются, LuCI обновляется. APK удаляет ставшие ненужными зависимости. Если sing-box нужен другому приложению, его пакет, сервис и настройки сохраняются. NextDNS, Passwall и другие самостоятельные VPN эта опция не удаляет. Повторный запуск после успешного удаления сообщает, что пакеты уже отсутствуют. Архив резервной копии остаётся на роутере; `--generic` и `--uninstall` одновременно не поддерживаются.

## Hysteria 2

Добавьте в секцию AnticheburNET ссылку `hysteria2://` от сервера или собственный sing-box outbound. Например, в поле JSON outbound:

```json
{
  "type": "hysteria2",
  "tag": "HY2",
  "server": "vpn.example.com",
  "server_port": 443,
  "password": "REPLACE_WITH_SERVER_PASSWORD",
  "tls": {"enabled": true, "server_name": "vpn.example.com"}
}
```

При необходимости добавьте согласованные с сервером параметры obfs/port hopping. В рабочей конфигурации используйте действительный сертификат и имя сервера. Набор сборки включает `with_quic`; тест передаёт HTTP через реальный зашифрованный Hysteria 2 туннель. Naive/Chromium в комплект не включён.

## Опциональное ядро Xray 26.10.21

По умолчанию этот пакет отсутствует. Для нативных профилей сначала отдельно установите проверенный по SHA256 `anticheburnet-xray_26.10.21-r1_aarch64_cortex-a53.apk`, если он опубликован в выбранном релизе. Стандартная установка и обновление удаляют ранее установленный Xray после резервного копирования настроек. Порядок перехода со старых обновляторов описан в [документе миграции](XRAY-OPTIONAL-MIGRATION.md).

Для REALITY при генерации конфигурации sing-box extended 2.7.2 и новее AnticheburNET включает
`tls.reality.support_x25519mlkem768=true`, сохраняя uTLS fingerprint, указанный в конфигурации.
Если fingerprint не задан, используется `chrome` (`HelloChrome_133` в закреплённом uTLS v1.8.7),
который содержит `X25519MLKEM768`. Параметр сохраняет гибридный key share,
который предоставляет выбранный fingerprint; он не добавляет его к пресетам без ML-KEM.
Для Xray начиная с 26.9.8 выбранный пресет должен предлагать гибридный share перед `X25519`.
Явно заданные пресеты сохраняются; Firefox-пресет (`HelloFirefox_120`) этого share не содержит.
Правило действует для ручных ссылок, импортированных и уже сохранённых подписок и JSON-узлов.
Для старого сервера можно явно задать `tls.reality.support_x25519mlkem768=false` в JSON узла;
его fingerprint сохранится. Официальному sing-box и старым extended этот параметр автоматически не добавляется.

sing-box extended сохраняет свою реализацию XHTTP. Для параметров, доступных именно в Xray, используйте штатный Xray: импортируйте нативный JSON с `outbounds`, `routing`, `dns`, `policy` и необходимыми настройками, полученный от вашего сервера. В частности, `vless`, REALITY, XHTTP и их дополнительные поля не преобразуются в ограниченную схему sing-box.

```sh
chmod 600 /root/xray-native.json
anticheburnet-xray-import /root/xray-native.json
uci set anticheburnet_xray.settings.enabled='1'
uci commit anticheburnet_xray
/etc/init.d/anticheburnet-xray restart
```

Импорт сначала создаёт кандидат с правами `600`, проверяет его самим `xray run -test` и только после успеха заменяет рабочий файл. Подготовка управляет двумя вещами: заменяет `inbounds` единственным SOCKS-входом **127.0.0.1:10810 с UDP** и устанавливает `streamSettings.sockopt.mark=134217728` каждому outbound для обхода повторного TPROXY. Остальные поля сохраняются. Если ваши routing rules ссылались на старые inbound tags, замените их на `anticheburnet-socks`. Полные GeoIP/GeoSite из официального архива входят в пакет в `/usr/share/xray/geodata.tar.gz`; helper `anticheburnet-xray-assets` автоматически предоставляет Xray проверенную копию в RAM. Ручной запуск Xray с geo-rules требует `export XRAY_LOCATION_ASSET=$(anticheburnet-xray-assets)`.

В нужную секцию AnticheburNET добавьте:

```json
{"type":"socks","tag":"Xray 26.10.21","server":"127.0.0.1","server_port":10810,"version":"5"}
```

При routing через FakeIP оставьте разрешение доменов в AnticheburNET. Для сложной собственной DNS-конфигурации Xray проверьте, что её запросы направляются через маркированный outbound и не возвращаются в TPROXY. Нативное ядро предоставляет все свои протоколы; importer управляет локальным входом и не публикует серверные входы в WAN. CI проверяет SOCKS-передачу данных, но не все возможные серверные комбинации Xray.

## Подписки Happ и маршрутизация

Обычную HTTP(S)-ссылку подписки Happ добавляйте в секцию AnticheburNET. При необходимости задайте
User-Agent `Happ`. Узлы VLESS/Hysteria 2 импортируются из обычного или base64-кодированного
списка ссылок. ECHConfigList из параметра `ech` Hysteria 2 преобразуется в PEM-конфигурацию
ядра. Закрытые `happ://crypt...` ссылки требуют исходной HTTP(S)-ссылки провайдера;
приватная подписка не передаётся сторонним сервисам расшифровки.

Заголовки `Routing` и `Routing-Enable`, а также строки `happ://routing/add/...`,
`happ://routing/onadd/...` и `happ://routing/off` в теле подписки обрабатываются вместе с узлами.
Применяются `RouteOrder`, `GlobalProxy`, `Direct/Proxy/BlockSites`, `Direct/Proxy/BlockIp`,
`DomainStrategy`, Remote/Domestic DNS и `DnsHosts`. Доменные префиксы `domain:`, `full:`,
`keyword:` и `regexp:` сохраняют своё значение; `geoip:` и `geosite:` читаются из DAT-файлов,
указанных провайдером. DAT кэшируются на неделю в `/tmp/anticheburnet-happ-<секция>`, занимая RAM.
Неподдерживаемый или повреждённый профиль вызывает явную ошибку; он не заменяется другой политикой.
Для этой версии используйте профили с `FakeDNS=false` и IP-адресами в `DnsHosts`.

Правила провайдера действуют внутри условий своей секции и в её локальном mixed proxy.
Для полного покрытия клиентов задайте секцию для всего нужного трафика. Пустая секция
с активным профилем Happ использует глобальную политику провайдера. Более ранние секции
AnticheburNET сохраняют приоритет. Разные активные профили требуют отдельных секций.
Для DNS учитываются доменные условия и адреса клиентов; порты приложений и IP назначения
остаются условиями маршрутизации трафика, поскольку DNS-вопрос их ещё не содержит.
При фильтре по адресам устройств их DNS перехватывается с сохранением исходного адреса клиента.
Изменение только маршрутизации вызывает перегенерацию конфигурации.
DNS сохраняет соответствие реального IP доменному имени (`reverse_mapping`), чтобы
правила по доменам действовали и для IP-соединений клиентов; sniffing включён для IPv4/IPv6.
Если клиент обходит DNS роутера, домен доступен только при успешном sniffing протокола.
Android-списки `Per-App-Proxy` не применимы к маршрутизатору: для отдельных устройств
задавайте исходные IP/подсети в AnticheburNET.

## AmneziaWG 3.1

Для AWG подписка может содержать `.conf`, JSON endpoint/outbound sing-box extended или
Mihomo с `amnezia-wg-option` (JSON/YAML) для AmneziaWG 3.1. JSON/YAML WireGuard без параметров AWG
не переименовывается в AmneziaWG 3.1. Для явно импортируемого `.conf` применяются проверки
полей и ключей официального AWG 3.1. Если профилей несколько, выберите точное имя:

```sh
anticheburnet-awg-import --list 'https://provider.example/subscription'
anticheburnet-awg-import --profile 'AWG profile' 'https://provider.example/subscription'
uci set anticheburnet_awg.settings.subscription_url='https://provider.example/subscription'
uci set anticheburnet_awg.settings.subscription_profile='AWG profile'
uci commit anticheburnet_awg
```

Ссылка обновляется при старте/перезапуске `anticheburnet-awg`. При ошибке загрузки сохраняется
последняя конфигурация; неоднозначный профиль, неверный ключ и shell hooks отклоняются.
Конфигурация записывается атомарно с правами `0600`. Переданные правила Happ сохраняются
в комментарии конфигурации и применяются секцией AnticheburNET, использующей управляемый
интерфейс (по умолчанию `awg0`). После обновления AWG и выбора его интерфейса примените
настройки AnticheburNET или выполните `/etc/init.d/anticheburnet restart`, чтобы обновить маршрутизацию.
Доступная проверенная подписка пока содержит только VLESS/Hysteria 2; формат реального
AWG-профиля провайдера следует подтвердить после его появления.

Скопируйте конфигурацию AWG 3.1 от вашего сервера в `/etc/anticheburnet/awg0.conf` и установите права. Настройки клиента должны совпадать с сервером: частный/публичный ключи, Endpoint, Address, AllowedIPs и параметры обфускации.

```sh
chmod 600 /etc/anticheburnet/awg0.conf
uci set anticheburnet_awg.settings.enabled='1'
uci commit anticheburnet_awg
/etc/init.d/anticheburnet-awg restart
awg show awg0
ip link show awg0
```

В AnticheburNET выберите тип outbound **интерфейс** и устройство **awg0**. Если `awg0` не появляется в списке netifd, добавьте интерфейс `awg_anticheburnet` с protocol `none`, device `awg0`, без default route; затем выберите его в AnticheburNET. Данные направляются через sing-box `bind_interface=awg0`; создание самого туннеля выполняет `anticheburnet-awg`.

Поддержаны `Jc/Jmin/Jmax`, `S1..S4`, диапазоны `H1..H4`, `I1..I5`, `HeaderProtectionKey`, `ContentPaddingAddition`, диапазоны времени rekey/keepalive/handshake, `RandomTrailers` и `DisableCookies`. Их окончательно проверяет официальный `awg-tools` 3.1. Неподдерживаемые поля и `PreUp/PostUp/PreDown/PostDown` отклоняются; shell hooks не выполняются. `Address` и `MTU` применяются сервисом; `DNS`, `Table` и пользовательский `FwMark` не применяются, поскольку DNS и выбор маршрута принадлежат AnticheburNET. Endpoint может содержать DNS-имя.

`AdvancedSecurity=on` в `[Peer]` принимается как штатный режим userspace 3.1. Этот legacy-флаг tools предназначен для kernel API и не передаётся Go-демону, который всегда работает в режиме AWG. Значение `off` отклоняется с пояснением; обычный WireGuard используйте отдельным интерфейсом, независимо от AmneziaWG 3.1.

Сервис использует `/dev/net/tun` и userspace `amneziawg-go`, поэтому внешний модуль ядра AWG не нужен. Поддерживается один управляемый туннель, по умолчанию `awg0`, с отдельной routing table **311** и rules priority **10400** только для трафика, привязанного к интерфейсу. Основной WAN default route не заменяется. Занятая таблица 311 или существующий `awg0` блокируют старт; сервис не должен управлять интерфейсом одновременно с netifd AWG или другим VPN-клиентом.

## Проверка и диагностика

```sh
sing-box version
xray version
amneziawg-go --version
awg --version
sing-box check -c /etc/sing-box/config.json
logread -e anticheburnet -e sing-box -e xray -e amnezia
awg show awg0 latest-handshakes
```

Успешная сборка и QEMU-проверка не измеряют производительность физических устройств. Для подтверждения работы на устройстве нужны сохранение состояния после reboot, проверки IPv4/IPv6/DNS через выбранные секции, реальные HY2/Xray/AWG серверы и замер скорости. Не включайте одновременно несколько независимых программ перехвата трафика без согласованной маршрутизации.

Стандартный комплект содержит пять APK, без Xray. При чистой установке и обновлении установленный Xray удаляется после резервного копирования настроек. Нативный Xray можно установить отдельно, когда нужен специфический профиль. sing-box extended обновлён до 1.14.3 / 2.7.3 с Go 1.26.10 и проверкой REALITY ML-DSA; импорт сохраняет расширенные XHTTP extra и отдельный download. Подробности и переход со старых обновляторов: [миграция](XRAY-OPTIONAL-MIGRATION.md).
