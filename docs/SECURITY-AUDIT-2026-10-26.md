# Проверка безопасности и приватности AnticheburNET

Дата: 26 октября 2026 года. Проверенный checkout: `f9dda314`, версия 1.0.32.

Последующее изменение в рабочем дереве: определение стран через `api.country.is`
заменено локальной MMDB-базой. См. [локальная GeoIP](LOCAL-GEOIP.md). Ниже сохранён
результат исходного аудита версии 1.0.32 до этого исправления.

## Вывод

В проверенных участках исходного кода не обнаружен механизм скрытой отправки конфигураций, паролей или журналов автору программы. Это ограниченный вывод статического анализа, а не доказательство отсутствия любых закладок во всех зависимостях и готовых бинарных файлах.

Программа действительно передаёт данные внешним сторонам. Помимо VPN-трафика и DNS, при загрузке подписки передаются постоянный идентификатор устройства, модель роутера и версия ядра. Есть подтверждённые недостатки защиты API, разграничения прав и обработки перенаправлений. Режим «Всё в туннель» не означает отсутствие прямых соединений.

## Объём и метод

Проверены точки внешних запросов, загрузка подписок и Happ, генерация sing-box, DNS, LuCI/RPC ACL, CLI, установка и обновления, остановка и аварийная очистка. Дополнительно просмотрены локальные исходники Clash API из `.build/sing-box-extended`, обёртки Xray и AmneziaWG и собственные изменения провайдера sing-box.

Существующий граф graphify содержит старые имена `forkop`; он использован только для начальной навигации. Основание выводов — текущие исходники.

Семь ключевых файлов из локально сохранённых пакетов `anticheburnet_1.0.32.ipk` и `luci-app-anticheburnet_1.0.32.ipk` сопоставлены с checkout: совпадают с нормализацией CRLF/LF. Это не проверка текущей публикации в интернете и не проверка установленного экземпляра. Упакованный `/etc/config/anticheburnet` имеет режим `0644`.

Локальные пробы извлечённых функций подтвердили ветви генерации API и заголовков. Отдельный реальный curl-запрос между двумя loopback-серверами подтвердил пересылку пользовательских заголовков при смене хоста. Использованы только вымышленные идентификаторы. Эти пробы не заменяют выполнение ucode на OpenWrt.

Доказательства сохранены в `.audit/security-2026-10-26/`: `check.cjs`, `results.json`, `package-comparison.json`. Запуск: `node .audit/security-2026-10-26/check.cjs` из корня проекта. Для curl-пробы нужен Windows и доступ к запуску дочернего процесса.

## Кто получает данные

| Получатель | Передаваемые данные | Когда |
| --- | --- | --- |
| Провайдер указанной пользователем подписки | URL/токен подписки, исходящий IP, User-Agent, X-HWID, модель, ОС, версия ядра, языковые заголовки | При загрузке и автообновлении подписки |
| Хост назначения HTTP-перенаправления подписки | В том числе X-HWID и модель из исходного запроса | Если сервер подписки отвечает редиректом |
| DNS-сервер, по умолчанию `77.88.8.8` | Запрашиваемые доменные имена и исходящий IP; по умолчанию UDP без шифрования | При DNS-разрешении; конкретный набор запросов зависит от правил/FakeIP |
| `ip.podkop.fyi`, `fakeip.podkop.fyi` | Исходящий IP, время запроса; при обращении из браузера — обычные HTTP-метаданные браузера | Во время соответствующих диагностических проверок |
| `api.country.is` | Массив публичных IP-адресов узлов подписки и IP источника запроса | При выбранном методе `country_is` и активном фильтре стран; по умолчанию используется `flag_emoji` |
| `www.gstatic.com/generate_204` | Исходящий IP и время проверки | Проверка задержки/доступности; для проверки через узел виден IP этого узла |
| GitHub API, release assets, raw.githubusercontent.com | IP, запрошенные репозитории/файлы/версии, HTTP-метаданные | Проверки обновлений, установка, загрузка выбранных списков |
| `MetaCubeX/Yacd-meta` на GitHub | Запрос ZIP веб-панели | При включении YACD, если каталог панели пуст |
| Настроенные VPN/прокси-узлы | Сам трафик, адрес источника и доступные транспортные метаданные | По правилам маршрутизации |
| Настроенные Happ DNS и URL geodata | DNS-запросы либо загрузка ресурсов | При применении политики Happ |
| Tailscale control plane | Данные, необходимые для регистрации и работы узла | Только при включённом соответствующем endpoint |

Обычное использование VPN не даёт его оператору автоматически читать содержимое корректно защищённого HTTPS. Оператор при этом остаётся стороной, которой доверяют транспорт и часть метаданных. В проверенном загрузчике подписки нет дополнительного POST с содержимым конфигурации роутера; перечисленные заголовки отправляются явно.

## Подтверждённые проблемы

### 1. Высокий риск: API управления доступен без аутентификации на LAN

Источники: `anticheburnet/files/usr/lib/singbox/generator.uc:428`, `anticheburnet/files/usr/lib/singbox/runtime.uc:583`, `anticheburnet/files/etc/config/anticheburnet:25`.

`clash_api_config()` всегда добавляет `external_controller`. Адрес обычно берётся у интерфейса `lan`. `enable_yacd=0` отключает только веб-панель: поле `secret` при этом вообще не добавляется, даже если ключ сохранён в настройках. Для тестового LAN-адреса результат — `{ "external_controller": "192.0.2.1:9090" }`.

В локальном исходнике ядра `experimental/clashapi/server.go` middleware при пустом `serverSecret` пропускает запрос без проверки. Зарегистрированы `/connections`, `/proxies`, `/logs` и другие методы. Поэтому клиент, имеющий сетевой доступ к 9090, может читать метаданные соединений, переключать выбранные прокси и закрывать соединения без входа в LuCI. Произвольное выполнение команд через этот API данным аудитом не установлено.

При `enable_yacd=1` и `enable_yacd_wan_access=1` допускается `0.0.0.0:9090` без секрета. Доступность из WAN зависит от firewall и проброса портов; автоматически открытый WAN не утверждается. HTTP/WS используются без TLS (`fe-app-anticheburnet/src/helpers/getClashApiUrl.ts:18`).

Исправление: обязательный случайный ключ API независимо от YACD; по умолчанию loopback и обращения через проверяемый RPC; для необходимого сетевого доступа — аутентификация, ограничения firewall и TLS.

### 2. Высокий условный риск: право чтения LuCI разрешает изменяющие команды

Источники: `luci-app-anticheburnet/root/usr/share/rpcd/acl.d/luci-app-anticheburnet.json:4`, `anticheburnet/files/usr/bin/anticheburnet:133`.

В разделе `read.file` разрешён `exec` для всего `/usr/bin/anticheburnet` и `/etc/init.d/anticheburnet`, без ограничения аргументов. CLI содержит `stop`, `uninstall`, `component_action`, `release_auto_update` и другие изменяющие операции. Сам CLI не проверяет роль веб-сессии.

Следствие: отдельной учётной записи LuCI с правом чтения этого приложения нельзя доверять как наблюдателю. Выданное право запуска охватывает и изменяющие операции в контексте службы RPC. Условие — наличие аутентифицированной сессии с соответствующим ACL и доступом к file.exec; это не обход входа анонимным пользователем. Воспроизведение на реальном rpcd в этом аудите не выполнялось.

Исправление: отдельные RPC-методы с проверкой прав и аргументов; чтению разрешать только операции чтения, изменяющие действия вынести в write. Не передавать клиенту универсальный исполняемый CLI как разрешённый инструмент наблюдения.

### 3. Средний риск приватности: постоянный HWID и сведения об устройстве уходят провайдеру

Источники: `anticheburnet/files/usr/lib/subscription/cache.uc:728`, `:758`, `:1542`, `:1585`; `anticheburnet/files/usr/lib/config/connections.uc:639`, `:773`.

HWID образуется из MAC `eth0` (либо `br-lan`) и модели роутера через MD5 с усечением до 16 шестнадцатеричных символов. Это не сырой MAC, но стабильная производная, позволяющая сопоставлять обращения одного устройства. Значение одинаково для разных провайдеров при одинаковых исходных данных.

В запрос всегда добавляются `X-HWID` и User-Agent. По умолчанию добавляются `X-Device-OS: OpenWrt Linux`, `X-Device-Model`, `X-Ver-OS`, `Accept-Language`, `X-Device-Locale`.

Выключение автоматического HWID означает переход к ручному значению. Пустое значение снова заменяется сгенерированным HWID. Таким образом, явного режима полного отсутствия заголовка в проверенном загрузчике нет. `custom_device_headers=0` также означает реальные заголовки по умолчанию, а не прекращение их отправки.

Исправление: явные независимые настройки отправки идентификатора и сведений об устройстве. Для требующих HWID провайдеров — отдельный случайный идентификатор на источник. Миграция должна сохранять работоспособность подписок с привязкой к существующему HWID.

### 4. Средний риск: заголовки подписки передаются произвольному хосту редиректа

Источник: `anticheburnet/files/usr/lib/subscription/cache.uc:1552`.

Загрузка использует curl `-fL` совместно с `-H X-HWID` и другими пользовательскими заголовками. В коде нет проверки, что следующий хост совпадает с исходным, и нет запрета понижения HTTPS до HTTP. Поддержка обычного HTTP для ссылок также предусмотрена.

В локальной пробе запрос к `127.0.0.1` был перенаправлен на `localhost` с другим портом; принимающая сторона получила вымышленные `X-HWID` и `X-Device-Model`. Такое поведение пользовательских заголовков описано и в [официальном руководстве curl](https://curl.se/docs/manpage.html#-H).

Для злоупотребления нужен управляемый/скомпрометированный сервер подписки, его перенаправление либо возможность подменить незашифрованный HTTP-ответ. Это возможность утечки, а не доказательство, что конкретный провайдер её использует.

Исправление: HTTPS по умолчанию и запрет downgrade; проверять каждый переход, не пересылать идентифицирующие заголовки другому origin без явной настройки. Учесть легитимные перенаправления провайдеров.

### 5. Высокий условный риск: цепочка доверия к обновлениям недостаточно защищена

Источники: `anticheburnet/files/usr/lib/components/action.uc:498`, `:1193`, `:1313`, `:1635`, `:1927`; `install.sh:1971`; `components/versions.env`.

Основной согласованный релиз проверяет SHA256 пакетов по скачанному `SHA256SUMS`. Это полезная проверка целостности. Но манифест загружается из того же релиза и не проверяется независимым закреплённым ключом. Локальные APK устанавливаются с `--allow-untrusted`. При компрометации издателя/аккаунта релиза атакующий может заменить и пакет, и контрольную сумму.

Отдельный путь `sing-box-extended compressed` обращается к `shtorm-7/sing-box-extended`, загружает архив, извлекает бинарный файл и запускает его с аргументом `version`. Проверка лишь ищет `extended` в ответе. На этой ветке не обнаружена проверка SHA256/подписи перед запуском скачанного кода. Простая проверка версии уже выполняет этот код в контексте обновляющей службы.

По умолчанию автоматическая установка релизов выключена (`release_auto_update_enabled=0`); проверки наличия обновлений включены. Этот риск не означает, что программа сама ежедневно устанавливает произвольные обновления. В сборке основных компонентов уже есть закреплённые commit и SHA256 входных артефактов — это положительная мера, но не замена проверке скачанного обновления.

Исправление: подписывать манифесты и проверять закреплённый публичный ключ; одинаковая проверка для каждой ветки установки до любого запуска бинарника. Веб-панель YACD также желательно поставлять проверенной частью пакета вместо загрузки изменяемой ветки `gh-pages`.

### 6. Средний локальный риск: конфигурация может читаться непривилегированным процессом

Источники: `install.sh:2369`, данные локального IPK 1.0.32 в `package-comparison.json`.

Файл `/etc/config/anticheburnet` в проверенном пакете имеет режим `0644`; миграция старой конфигурации прямо выполняет `chmod 0644`. Конфигурация может содержать URL подписок с токенами, UUID, пароли и ключи. При доступных родительских каталогах режим позволяет чтение любому локальному Unix-пользователю/процессу. Это локальная экспозиция, не автоматическая отправка в интернет.

Исправление: `0600` для содержащих секреты конфигураций и проверка прав после миграции/обновления. Отдельно проверить права сгенерированного sing-box JSON и runtime-файлов на работающей системе. Постоянный кэш подписок уже защищается `0700`/`0600`; это полезная существующая защита.

## Прямой трафик и ожидания приватности

1. **BitTorrent обходит туннель.** В `anticheburnet/files/usr/lib/singbox/route.uc:45` правило распознанного `bittorrent` направляет его в direct перед политиками секций. Это также прямо описано в `README.md:44`, включая режим «Всё в туннель». Пиры могут увидеть внешний адрес прямого подключения. Это явное поведение продукта, а не скрытая закладка.
2. **DNS по умолчанию не защищён туннелем.** В конфигурации UDP `77.88.8.8`, `dns_detour_enabled=0`; `singbox/dns.uc:40` не задаёт detour. В просмотренном ядре `dns/transport_dialer.go` создаёт dialer без `DefaultOutbound`, а `common/dialer/dialer.go` выбирает обычный сетевой dialer при пустом detour. Поэтому при стандартной маршрутизации самого роутера запросы идут напрямую. Фактический путь может изменяться внешним VPN/политиками OpenWrt. Для приватного режима нужны шифрованный DNS и осознанная настройка маршрута; bootstrap DNS требует отдельного внимания.
3. **Очистка не сохраняет блокировку прямого выхода.** `service/lifecycle.uc:748` удаляет nft-таблицу перехвата и policy routes; `:786` вызывает эту очистку после ошибки запуска/перезагрузки и восстанавливает DNS. При обычном разрешённом LAN→WAN это позволяет последующий прямой доступ. Утверждение не распространяется автоматически на каждый кратковременный обрыв VPN: конкретное поведение зависит от ошибки и состояния правил. Если нужен запрет выхода без VPN, требуется отдельная сохраняющаяся firewall-политика/kill switch.
4. **Подписке доверяется маршрутизация.** В режиме Happ внешний провайдер может менять Direct/Proxy/Block и Remote/Domestic DNS (`subscription/happ.uc:19`, `singbox/happ.uc`). Это заявленная возможность, но компрометация провайдера способна изменить маршрут трафика без изменения кода приложения.
5. **Проверка сертификата может быть отключена самим профилем.** Парсер поддерживает `allowInsecure`/`insecure`, генератор сохраняет соответствующий TLS-флаг. Наличие поддержки не означает, что она включена во всех профилях. Такие узлы нужно отдельно помечать и проверять, если требуется защита от подмены сервера.

## Что не подтверждено и что осталось проверить

- Не обнаружены в просмотренном собственном runtime-коде трекеры аналитики, автоматическая загрузка конфигов/журналов на сервер автора, скрытый SSH-ключ или обратная командная оболочка. Поиск строк не доказывает отсутствие более сложной закладки.
- Не проводились дизассемблирование и полный аудит sing-box/Xray/AmneziaWG, всех Go/npm-зависимостей и загружаемой YACD. Совпадение готовых ядер с исходниками не доказано воспроизводимой сборкой.
- Не проверены работающий роутер, его учётные записи, файлы секретов, nft/fw4, открытые порты и установленные пакеты. Не снимался pcap. Поэтому факт конкретной утечки с конкретного устройства не утверждается.
- Для проверки установленного экземпляра нужны сравнение версий/хешей, просмотр слушающих сокетов и firewall, проба отказа VPN и захват WAN-трафика при запуске, обновлении подписки, диагностике и простое. Захват должен учитывать, что сам VPN-трафик и HTTPS-запросы скрывают содержимое от pcap.

## Порядок исправлений

Сначала защитить 9090 и убрать изменяющие CLI-команды из права чтения. Затем добавить отключение передачи HWID/сведений об устройстве и безопасные перенаправления. Следом — независимая проверка обновлений и права `0600`. Для режима строгой приватности отдельно согласовать обработку BitTorrent, DNS и запрет выхода без VPN.

Настройки роутера и рабочий код в ходе аудита не изменялись. Созданы только этот отчёт и локальные материалы проверки.
