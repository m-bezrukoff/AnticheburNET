# Совместимость AnticheburNET с Xray-core 26.10.21

После этого аудита реализована миграция к опциональному Xray, обновлена база sing-box и исправлен импорт. Текущее поведение и ограничения описаны в [документе миграции](XRAY-OPTIONAL-MIGRATION.md). Ниже сохранён исходный результат проверки до реализации.

Дата проверки: 26 октября 2026 года. Область: текущие исходники AnticheburNET, закреплённые зависимости, разница Xray 26.10.10 → 26.10.21 и локальные межъядерные проверки. Код продукта, версии зависимостей и установленные роутеры в рамках этого аудита не изменялись.

## Вывод

Обычные VLESS, VLESS Vision, REALITY, VLESS Encryption и базовые режимы XHTTP совместимы с сервером Xray 26.10.21. Это подтверждено передачей HTTP, HTTPS/TLS 1.3 и UDP на локальном стенде. Требования немедленно заменить реализацию протоколов sing-box из-за номера версии сервера нет.

Обновление компонентов безопасности необходимо: в проекте всё ещё закреплён отозванный Xray 26.10.10, а сборочный Go 1.26.8 предшествует исправлению проверки сертификатов. Для полноты импорта новых конфигураций необходимо отдельно исправить конвертер подписок. Смена версии sing-box сама эти потери полей не исправит.

## Что изменилось в Xray

Сопоставлены 35 коммитов после `701af60772cda123492f86e383e1fdba066614a9` (26.10.10) до `1b1647cd9ddf0abc34b981d4611fc03bcac1ca74` (26.10.21). Теги 26.10.10 и 26.10.17 отозваны, поэтому сравнение использует SHA исходной версии. Полных release notes upstream на дату проверки ещё не опубликовал; перечень ниже получен из истории и diff.

| Изменение | Значение для AnticheburNET |
| --- | --- |
| Обновлены встроенные RootCAs; удалены три корневых сертификата, связанные с проблемными промежуточными CA. Официальный бинарник собран Go 1.27.3 | Срочно заменить наш нативный Xray 26.10.10. Это исправление доверия TLS, а не смена протокола VLESS |
| REALITY синхронизирован с Go 1.27; ML-DSA и HKDF переведены на стандартную библиотеку | Обычный REALITY с нашей реализацией работает. Не следует путать ML-KEM обмен ключами и ML-DSA проверку подписи |
| Исправлена работа Vision с изменившимся внутренним TLS `rawInput` | Исправление внутри процесса Xray. Старый клиент sing-box не обязан использовать тот же Go, что сервер |
| XDRIVE: HTTP/3, XMUX, браузерные HTTP-заголовки, двухшаговые template-операции `hrefPath` | Для применения нужен нативный Xray; конвертер sing-box XDRIVE не реализует |
| XDRIVE требует VLESS Encryption и клиентский Mux; имя сервиса `google-drive` | Возможна несовместимость старых XDRIVE JSON. Это требование конкретно XDRIVE, а не всех VLESS-подключений |
| Finalmask: фильтр исходных адресов на TCP/UDP inbound; Lua для noise; DoH для XDNS | Не переносится автоматически в обычный sing-box outbound; нативный Xray сохраняет конфигурацию. Наш helper заменяет inbounds, поэтому inbound-фильтры исходного файла не сохраняются |
| Lua: sandbox по умолчанию, inline-скрипты отключены, добавлены проверки безопасности и команды base64 | Произвольные старые Lua-конфигурации требуют отдельной миграции и проверки `xray run -test` |
| TUN, WireGuard и MASQUE используют встроенный лёгкий TCP/IP stack; оптимизирован приём крупных TCP-сегментов Linux | Наш основной TUN/TPROXY путь sing-box от этого не меняется. Эффект возможен при использовании этих возможностей в нативном Xray |
| MASQUE: XMUX и Chrome User-Agent; исправления Hysteria, SS2022, HTTP server-first, SOCKS UDP timer и UDP dialer controllers | Полезные исправления нативного Xray; не являются основанием менять протокол AmneziaWG или Hysteria 2 в sing-box |
| Источник встроенных geodata сменился с Loyalsoldier на XTLS/Xray-rules-dat, GeoIP берётся из geoip-lite | При выпуске нового APK повторно проверить наличие используемых GeoIP/GeoSite категорий, упаковку, RAM и размер flash |
| Ограничены права Docker-конфигураций и файлов TLS key log | Наши OpenWrt init-скрипты не используют Docker. Нативный импорт уже создаёт конфигурацию с правами 0600 |

Изменения общего менеджера XMUX в этом diff обслуживают также новые транспорты; изменения wire-формата базового XHTTP здесь не обнаружены.

## Подтверждённые ограничения импорта

Проверены реальным ucode-интерпретатором в WASM на синтетических конфигурациях; результаты находятся в `.audit/xray-26.10.21-compat/import-results.json`.

1. `realitySettings.password` теряется при преобразовании Xray JSON в sing-box. Xray 26.10.21 принимает этот ключ как основной и сохраняет обратную совместимость с `publicKey`. Наш `xray_tls_from_stream()` читает `publicKey/public_key`, но не `password`. Получается REALITY без `public_key`, который не сможет подключиться. URI с обычным `pbk=` этого дефекта не имеют.
2. `mldsa65Verify` не переносится; в текущем `OutboundRealityOptions` sing-box такого поля нет. Поддержка `support_x25519mlkem768` не означает поддержку ML-DSA проверки. Нужен нативный Xray либо отдельная реализация этой возможности.
3. Сложные XHTTP settings и `extra` переносятся лишь частично. Продемонстрирована потеря `sessionPlacement/sessionKey`, `xPaddingObfsMode` и `downloadSettings`. Базовые `path`, `mode`, padding ranges и часть XMUX настроек поддерживаются. Само ядро extended умеет больше, чем конвертер.
4. Неизвестный `network: "xdrive"` не отклоняется явно: конвертер выдаёт VLESS без transport. Это не совместимый XDRIVE-клиент. Следует явно отклонять такой импорт или направлять пользователя в нативный Xray.

Это существующие пробелы конвертации, а не доказательство, что сервер 26.10.21 отключил старые клиенты. Нативный helper `components/xray/files/usr/lib/anticheburnet-components/xray.uc` сохранил `password`, ML-DSA, XHTTP extra и XDRIVE в проверенных fixtures. Он управляет только ingress и outbound mark; внешние Lua-файлы и ссылки на прежние inbound tags всё равно требуют подготовки.

## Что обновлять

### Срочное исправление безопасности

- Поднять нативный Xray до 26.10.21 вместе с SHA256, версией APK, документацией и контрактными fixtures. В `components/build.sh` версия APK задана отдельно от `XRAY_VERSION`, поэтому изменение одного `versions.env` недостаточно.
- Пересобрать наш sing-box Go **1.26.10 или более новым совместимым исправленным toolchain**. Go 1.26.8 не содержит исправления `GO-2026-6809 / CVE-2026-111943`. Повышать номер sing-box для этого необязательно.
- Обновить `ca-bundle`/системные CA OpenWrt и проверить активное хранилище. Генератор задаёт `certificate: {}`, а текущий sing-box по умолчанию использует системный store. Обновление Xray не исправляет доверие сертификатам в другом процессе sing-box, curl или системном TLS.
- Проверить и при необходимости обновить библиотеки TLS/HTTPS системного ПО через подходящие feeds OpenWrt. Протокол Xray не требует конкретной новой версии curl, ucode, dnsmasq или nftables.

Go 1.26.10 — предпочтительный минимальный шаг для текущей базы. Слепой переход sing-box на Go 1.27.3 рискован: `common/badtls/raw_conn.go` ожидает `rawInput` как struct, тогда как в новом Go это указатель; у Xray именно для этого есть исправление #7176. Нужна проверка TLS/Vision и при необходимости адаптация исходников. Это вывод из исходников, а не результат пересборки sing-box новым Go в этом аудите.

Защита crypto/x509 нужна даже при задержке обновления системного CA store. Замены только Xray или только CA bundle недостаточно для всей совокупности наших процессов. Go статически входит в Go-бинарники; установка Go на роутере не обновит уже установленный sing-box.

### Плановое обновление sing-box extended

На дату проверки доступен `v1.14.3-extended-2.7.3` от 19 октября. Он содержит исправления XHTTP (проверки параметров, обработка ошибочных HTTP-запросов, нормализация path, session ID и XMUX), HTTP/2, half-close, UDP destination в группах, DNS и lifecycle. Поэтому обновление рекомендуется как обслуживание и исправление ошибок, но не требуется для уже проверенных стандартных соединений с Xray 26.10.21.

Обновлять нужно наш fork с сохранением uTLS backport и атомарного managed provider API. В новой базе менялись managers/lifecycle и providers, поэтому нельзя заменить APK stock sing-box или просто перенести версии без проверки `prepare-providers.py`, выбора активного узла, соединений при обновлении подписок и отсутствия рестартов. Новое значение XMUX по умолчанию также может изменить число соединений и расход памяти.

AmneziaWG 3.1, его tools, UPX и ядро OpenWrt не требуют обновления для совместимости с этим Xray-сервером. Их независимые исправления безопасности и требования выбранной версии Go следует рассматривать отдельно.

## Что выполнено на стенде

Официальный Windows x64 Xray 26.10.21 скачан из release assets; SHA256 архива сверена с GitHub API:

`fc58c39ee2f2717b4c54d28d374362389e5319b20ae44aea76ea45a5243ec827`

Сервер сообщил `1b1647c`, Go 1.27.3. Клиент — существующая локальная Windows-сборка `1.14.1-extended-2.7.2-anticheburnet.3`, commit `5956780...`, Go 1.26.4, с локальным patched uTLS. Таким образом, это проверка протокольной базы и наших browser presets, а не тест готового ARM64 APK `.4/.5`.

Успешно выполнены **19 сценариев, 57 проверок**:

- VLESS RAW и VLESS Vision/TLS — 2 сценария.
- REALITY с Chrome, Firefox и Safari, с Vision и без — 6.
- XHTTP/TLS: auto, packet-up, stream-up, stream-one — 4.
- VLESS Encryption с X25519 и ML-KEM-768 authentication — 2.
- XHTTP/REALITY с Chrome, те же четыре режима — 4.
- sing-box → SOCKS → нативный Xray → origin — 1.

В каждом сценарии проверены точное содержимое HTTP-ответа 256 KiB, HTTPS-ответа 256 KiB через TLS 1.3 и UDP echo. Для REALITY использован отдельный локальный Go TLS target. Все адреса стенда — loopback, реальные подписки и серверные credentials не использовались. Freedom на тестовом сервере получил явное разрешение loopback для локального origin.

Скрипты и результаты: `.audit/xray-26.10.21-compat/probe.py`, `camouflage.go`, `results.json`, `import-probe.cjs`, `import-results.json`, `upstream-evidence.json`. Это локальные игнорируемые материалы аудита.

Не проверялись: конкретная конфигурация внешнего сервера пользователя, готовая ARM64/UPX сборка, OpenWrt marks/TPROXY и throughput, HTTP/3/CDN и разделённый XHTTP download, реальная работа XDRIVE/Finalmask/Lua и криптографическая ML-DSA проверка. Для выпуска обновлённых APK нужны существующие QEMU/runtime tests, проверка геоданных и лимита 35 MB, а затем smoke test роутера. Локальная совместимость не является подтверждением установки или деплоя.
