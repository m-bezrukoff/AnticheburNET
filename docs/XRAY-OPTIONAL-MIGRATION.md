# Опциональный Xray и обновление sing-box

Актуальная политика от 10 ноября 2026 года; ниже также сохранены результаты предыдущих этапов миграции. Публикация релиза и установка на роутер этим документом не подтверждаются.

Стандартный комплект содержит backend, LuCI, перевод, sing-box extended и AmneziaWG. Без нативных профилей установка через SSH и обновление через LuCI не требуют Xray APK и не скачивают его. Если включён JSON-профиль `type: "xray"` или standalone-служба Xray, выбирается и проверяется также пакет Xray. Отсутствие нужного asset останавливает обновление до замены служб. Контрольные суммы проверяются для каждого выбранного пакета; необязательный Xray в общем manifest не мешает проверке.

При чистой установке старые Xray-пакеты входят в существующий план замены. При обновлении неиспользуемый `anticheburnet-xray` и конфликтующий `xray-core` вызывают миграцию даже при совпадающей версии приложения: сначала загружаются и проверяются новые APK, проверяются обратные зависимости и сохраняются настройки, затем службы Xray останавливаются и отключаются, пакеты удаляются без force-флагов. Если Xray нужен чужому приложению, обновление останавливается до остановки служб. Настройки входят в закрытую резервную копию `/root/anticheburnet-backups/`; существующий backend и sing-box сохраняют пользовательскую конфигурацию.

Для перехода со старых обновляторов, требующих шесть APK, release workflow по умолчанию публикует также опциональный настоящий Xray 26.11.9. Старый обновлятор может установить его при первом проходе. Новый механизм статуса отличает такой результат от `suite_format: 2` и продолжает тот же UI job новым backend, завершая удаление неиспользуемого Xray. Не отключайте `include_xray` при публикации переходного релиза, пока нужно поддерживать обновление старым UI. Новый SSH-установщик выбирает пять обязательных APK и добавляет Xray для включённых нативных профилей. Сами сборки без опции `BUILD_XRAY=1` Xray не требуют. Для обновлений без UI старый планировщик выполнит миграцию при следующем запуске уже нового backend; для немедленного перехода используйте новый установщик.

Нативный Xray остаётся доступен отдельным APK, по умолчанию выключенным. Для его явной установки скачайте asset из выбранного релиза, проверьте SHA256 по manifest этого релиза и установите через `apk add --allow-untrusted /путь/anticheburnet-xray_26.11.9-r1_aarch64_cortex-a53.apk`. Настройка SOCKS-моста описана в `OPENWRT-25.12.md`. Включённая standalone-служба или нативные профили AnticheburNET сохраняют Xray при следующем стандартном обновлении; выключенный и неиспользуемый пакет удаляется.

sing-box обновлён до базы `1.14.3-extended-2.7.3`, локальная ревизия `anticheburnet.8`. Сборка требует Go 1.26.11 с исправлением crypto/x509; также закреплены x/crypto 0.58.0, x/net 0.61.0, x/sys 0.49.0, CIRCL 1.6.5, gRPC 1.84.0, chi 5.3.0, Brotli 1.2.7 и klauspost/compress 1.20.2. Исправлены четыре обнаруженные сканером уязвимости прежнего gRPC. Установка и обновление обновляют `ca-bundle` из подходящих feeds OpenWrt. Наши современные Firefox/Safari uTLS presets сохранены. Атомарный provider адаптирован к новому scoped lifecycle; ошибки обновления не публикуют неполный граф.

Импорт Xray JSON поддерживает `realitySettings.password` с приоритетом над прежним `publicKey`, а также `mldsa65Verify`. URI `pqv` преобразуется в `tls.reality.mldsa65_verify`. Проверка ML-DSA-65 реализована в sing-box, включая отказ при неверной подписи или отсутствии proof. Для сервера REALITY с ML-DSA требуется подходящий TLS target с достаточно большим handshake; это серверное требование, а не причина отключать проверку.

XHTTP импорт сохраняет session/sequence placement, padding obfuscation, HTTP method, session ID, buffer/range/XMUX-настройки и отдельные endpoint/TLS/параметры download. Download не перезаписывает настройки upload. Невозможное сочетание `stream-one` и download отклоняется. XDRIVE, неизвестные транспорты и Xray Finalmask при преобразовании отклоняются, а не превращаются в обычный RAW. Для них остаётся явный нативный Xray. Это не реализация XDRIVE или Lua внутри sing-box.

Проверки включают ucode fixtures планирования, миграции и старого UI handoff; изолированный SSH-установщик с fake APK; unit-тест ML-DSA; runtime-тест атомарных подписок и Happ правил; межъядерные HTTP/HTTPS/UDP и положительные/отрицательные ML-DSA сценарии. Точная ARM64 сборка и её QEMU проверки включены в component CI; локальная кросс-компиляция сама по себе не подтверждает QEMU, UPX, flash budget или работу физического роутера.

Локально прошли 25 межъядерных сценариев (включая gRPC), 71 frontend-тест валидации, сборка LuCI, проверки установщика/APK hooks и сохранения соединений/выбора/атомарных Happ правил. Собраны Windows x64 и Linux ARM64 бинарники. Govulncheck 1.1.4 для сборок с символами не обнаружил известных уязвимых используемых символов или импортируемых пакетов; имеется advisory для неиспользуемого OpenPGP в модуле x/crypto, который не входит в дерево импортов этих сборок. Проверка в CI выполняется на бинарнике с символами до strip/UPX, чтобы избежать консервативного приписывания ему всех пакетов модуля. Публикация APK и проверка роутера не выполнялись.

Ревизия `.7` отключает MPTCP по умолчанию в сборке sing-box. Опциональный Xray поднят до 26.10.31; 26.10.29 отозван upstream. Условия проверки и ограничения ядра описаны в `XRAY-26.10.31-COMPATIBILITY.md`; это изменение приложений не подтверждает исправление ядра установленного роутера.


## Xray 26.11.9 и sing-box `.8`

Встроенный `chrome` обновлён до реального пресета Chrome 155 с Trust Anchor IDs и GREASE для signature algorithms. Явные aliases Chrome 155/133 сохраняются при импорте; старый компонент сообщает о необходимости обновления. Сравнение нормализованных ClientHello с исходным захватом Chrome входит в сборку. Поддержка ML-DSA proof в REALITY сохраняется; общий ML-DSA X.509 из нового uTLS исполняется нативным Xray.

В редакторе JSON outbound можно выбрать нативный Xray и вставить полный клиентский JSON. В UCI такой элемент сохраняется как `{"type":"xray","tag":"имя","config":{"outbounds":[...]}}`. Сам JSON проверяется Xray до остановки служб при Apply. Подготовка заменяет входы локальным SOCKS с UDP и ставит outbound mark, сохраняя остальные поля. Управляемые процессы используют порты 10840–10847 и защищённые конфигурации в RAM; прежний standalone-мост 10810 остаётся отдельным режимом. Удаление профиля останавливает его управляемый процесс. Подписки обновляются без перезапуска неизменных нативных процессов; изменение самого нативного профиля требует Apply.

XDRIVE требует совпадающих версий клиента и сервера. Нативный путь проверяется с VLESS Encryption, mux.cool и локальным файловым backend: sing-box → SOCKS → Xray → XDRIVE → Xray. Это проверка передачи HTTP/HTTPS/UDP, а не работы реальных Google Drive/S3, пропускной способности роутера или эффективности против DPI. ARM64/UPX/QEMU и лимит размера проверяются release CI; локальные Windows тесты их не заменяют.
